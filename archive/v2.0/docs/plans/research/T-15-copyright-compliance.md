> 任务编号：T-15

## 1. 背景与目标

般若佛经阅读器 v2.0 是一个纯前端 Web 应用，涉及以下版权和合规敏感内容：

- **用户上传内容**：MDX/JSON/CSV 格式的词典文件，经书文本（txt）
- **项目内置内容**：50+ 条佛教术语词典，5 部佛经（心经、金刚经、阿弥陀经、地藏经、观音经）
- **用户数据**：IndexedDB 存储的阅读进度、书签、笔记、功德统计
- **开源依赖**：Vue 3、Vite、Vant、mdict-js 等第三方库

本报告旨在识别上述内容涉及的版权风险、隐私合规要求及开源协议兼容性问题，并给出明确的合规建议。

## 2. MDX 词典版权分析

### 2.1 用户上传词典的版权风险

#### 风险场景

| 场景 | 风险等级 | 说明 |
|------|----------|------|
| 用户上传商业词典（如付费购买的 MDX） | **高** | 该词典受著作权保护，用户未经授权分发可能侵权 |
| 用户上传网上免费下载的词典 | **中** | 免费不等于无版权，需查看词典作者的授权声明 |
| 用户上传自编词典 | **低** | 用户自编内容属其个人作品，无版权争议 |
| 用户上传公领域词典（如百年前的佛学辞典） | **低** | 已进入公有领域，但数字化版本可能存在新的著作权 |

#### 法律分析

根据《中华人民共和国著作权法》：

- 词典的词条选择、编排、释义撰写具有独创性，构成汇编作品或文字作品，受著作权保护
- 用户将他人享有著作权的词典上传至本平台，可能构成**信息网络传播权**侵权
- 平台方（即本项目）作为信息存储空间的提供者，适用**避风港原则**（《信息网络传播权保护条例》第22条），但需满足以下条件：
  1. 明确标示信息存储空间性质
  2. 不改变用户上传内容
  3. 不知道或不应知道侵权行为
  4. 接到权利人通知后及时删除

#### 本平台特殊性

本项目为**纯前端应用**，所有数据存储在用户浏览器本地（IndexedDB），不存在服务端存储和分发。这一架构在法律上显著降低了平台责任风险：

- 数据不经过任何服务器，不存在"向公众提供"的行为
- 每个用户的数据仅在其本地浏览器中存在
- 本质上等同于用户在自己电脑上使用词典软件

### 4.2 详细法律分析

#### 中国著作权法

根据《中华人民共和国著作权法》第二十一条：
- 公民作品的保护期为作者终生及其死亡后五十年
- 上述经书译者均已去世超过 1300 年，远超保护期限

#### 国际公约

根据《伯尔尼公约》第七条：
- 版权保护期为作者终生加死后 50 年（部分国家为 70 年）
- 上述译作在全球任何司法管辖区均已进入公有领域

#### 现代校勘本/标点本注意

需要区分的是：
- **古代译本原文**（无标点、繁体竖排）：公有领域
- **现代学者的校勘本、标点本、注释本**：校勘者/注释者对其独创性部分（标点、校勘记、注释）享有著作权
- **现代白话翻译**：译者对翻译作品享有著作权

本项目使用的是**古代译本原文**（经传统标点整理），属于公有领域内容，不涉及版权风险。但需注意：

| 内容类型 | 版权状态 | 本项目使用 |
|----------|----------|-----------|
| 古代译本原文（无标点） | 公有领域 | 是 |
| 传统标点整理版 | 公有领域（标点惯例不构成独创性） | 是 |
| 现代学者校勘注释 | 受保护 | 否 |
| 现代白话翻译 | 受保护 | 否 |
| 现代英文翻译 | 受保护 | 否 |

### 4.3 建议

- 在经书数据文件中添加注释说明译者年代和公有领域状态
- 如未来计划引入现代译本或注释版本，需取得相应授权

## 5. 用户隐私合规

### 5.1 数据存储分析

根据项目方案（`PROJECT_V2_PLAN.md`），IndexedDB 存储的数据包括：

| 数据类别 | 存储位置 | 是否上传服务器 | 是否涉及个人信息 |
|----------|----------|----------------|------------------|
| 阅读进度（章节、位置、时长） | 用户浏览器 IndexedDB | 否 | 否（行为数据，不关联身份） |
| 功德统计（诵读次数、日期） | 用户浏览器 IndexedDB | 否 | 否 |
| 书签（位置、备注） | 用户浏览器 IndexedDB | 否 | 否 |
| 用户笔记（对术语的理解） | 用户浏览器 IndexedDB | 否 | 否 |
| 用户设置（字体、主题等） | 用户浏览器 IndexedDB | 否 | 否 |
| 用户上传的词典文件 | 用户浏览器 IndexedDB + File Cache | 否 | 否 |

### 5.2 GDPR 合规分析

根据欧盟《通用数据保护条例》(GDPR)：

| GDPR 要求 | 本项目状态 | 说明 |
|-----------|-----------|------|
| 数据最小化 | **合规** | 仅存储功能必需的数据，不收集额外信息 |
| 用户同意 | **无需显式同意** | 数据仅存本地，不涉及跨境传输或第三方共享 |
| 数据主体权利 | **部分适用** | 用户可通过浏览器设置删除 IndexedDB 数据 |
| 数据泄露通知 | **不适用** | 无服务器端存储，无远程数据传输 |
| 隐私政策 | **建议提供** | 即使是纯本地应用，提供隐私声明可增加用户信任 |

### 5.3 中国《个人信息保护法》合规

根据《中华人民共和国个人信息保护法》：

| 要求 | 本项目状态 | 说明 |
|------|-----------|------|
| 个人信息定义 | **不涉及** | 存储的数据不包含可识别个人身份的信息（无姓名、邮箱、IP 等） |
| 单独同意 | **不需要** | 不涉及个人信息处理 |
| 数据跨境 | **不涉及** | 数据不离开用户设备 |
| 隐私政策 | **建议提供** | 虽然不是强制要求（因不涉及个人信息），但建议声明以增强透明度 |

### 5.4 结论与建议

**本项目为纯前端应用，数据完全存储在用户本地浏览器中，不涉及个人信息的收集、传输或处理。** 因此：

- **不需要**完整的隐私政策文档
- **建议**在设置页面或关于页面中添加简短的隐私声明，说明数据仅存储在本地
- **如果未来接入后端服务**（如云端同步功能），则必须制定完整的隐私政策

### 6.3 需要重点关注的依赖

#### mdict-js

mdict-js 是本项目最关键的第三方依赖，用于解析 MDX 词典格式。需确认其开源协议：
- 如果是 MIT/Apache/BSD/ISC 等宽松协议：与 MIT 兼容
- 如果是 GPL：由于本项目为前端 SPA 应用，mdict-js 在浏览器端运行，GPL 的"传染性"主要体现在**分发**环节。如果本项目作为 SaaS 服务提供（用户通过浏览器访问），GPL v3 的 AGPL 条款不适用，因此不强制开源。但**如果分发构建产物**（如让用户下载离线版本），则可能需要遵守 GPL 的要求
- 建议：在项目中使用前确认 mdict-js 的具体协议

#### lzo-wasm

lzo-wasm 是 mdict-js 的依赖，用于解压 LZO 压缩的 MDX 文件。同样需要确认协议。

### 6.4 Copyleft 协议注意事项

如果项目引入 GPL/LGPL/AGPL 协议的依赖：

| 协议 | 影响 | 应对 |
|------|------|------|
| GPL v2/v3 | 要求衍生作品也以 GPL 分发 | 仅在前端构建产物中使用时，作为 SaaS 服务不触发分发要求 |
| LGPL v2.1/v3 | 允许动态链接，不要求衍生作品开源 | 可以安全使用 |
| AGPL v3 | 即使作为 SaaS 服务也要求开源 | 需特别谨慎，可能影响项目闭源分发 |
| MPL 2.0 | 文件级 copyleft | 可以安全使用，修改的文件需开源 |

### 6.5 建议

1. **确认 mdict-js 和 lzo-wasm 的协议**，在项目中记录
2. **维护依赖协议清单**，在引入新依赖时检查兼容性
3. **在 LICENSE 文件中添加第三方依赖声明**，列出所有依赖及其协议
4. 如果 mdict-js 使用 GPL 协议，考虑在 README 中添加声明说明

## 7. 结论与建议

### 7.1 风险评估总结

| 风险领域 | 风险等级 | 核心结论 |
|----------|----------|----------|
| MDX 用户上传词典 | **低**（纯前端架构） | 数据不经过服务器，不构成"向公众提供"，避风港原则天然适用 |
| 内置词典 | **低** | 基于公共领域佛学知识整理，建议声明原创和 MIT 授权 |
| 经文文本 | **无风险** | 所有译本均为千年以上的古代翻译，明确属于公有领域 |
| 用户隐私 | **无风险** | 纯本地存储，不涉及个人信息收集，无需完整隐私政策 |
| 开源协议 | **低** | 主要依赖均为 MIT/ISC，mdict-js 和 lzo-wasm 需确认协议 |

**本项目的纯前端架构天然规避了大部分版权和合规风险。** 由于所有用户数据存储在浏览器本地、不经过任何服务器，平台责任风险极低。内置经文文本属于公有领域内容，无版权争议。主要关注点在于确认关键依赖（mdict-js）的协议兼容性，以及添加适当的声明文件以增强透明度。
