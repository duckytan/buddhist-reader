# 书签功能 分析报告

> 任务编号：T-21
> 完成日期：2026-05-02
> 基于：docs/PROJECT_V2_PLAN.md

## 1. 背景与目标

v2.0 项目方案中将书签功能列为 P2 优先级，安排在 Phase 3 开发。当前 v1.0 的阅读进度仅保存位置信息，缺少书签标记能力。

**目标**：为般若佛经阅读器设计一套简洁实用的书签系统，满足用户标记重要经文段落、快速回看、诵读复习的需求。设计需符合"简单、专注、不打扰"的核心理念，避免过度设计。

## 2. 同类 App 对比

| App | 添加方式 | 分类/标签 | 检索 | 导出 | 特点 |
|-----|----------|-----------|------|------|------|
| **微信读书** | 阅读页右上角菜单"添加书签"，或与长按文字批注关联 | 无分类，与笔记混合展示 | 在"笔记"页可筛选"仅显示书签" | 无直接导出；依赖第三方工具（浏览器插件）导出为 Markdown/TXT | 书签与笔记强关联，无独立书签管理 |
| **Kindle** | 阅读时按菜单键添加书签；长按文字做标注（Highlight） | 无分类，按书籍组织 | "我的剪注"(My Clippings) 按书名+时间排序 | 原生无导出；通过 USB 提取 `My Clippings.txt`；第三方工具（Clippings Store）支持标签和导出 | 书签、标注、笔记三合一，数据封闭 |
| **Apple Books** | 点击顶部书签图标添加/移除；关闭书籍自动保存阅读位置 | 无分类，按书籍分"目录/书签/笔记"三栏 | 目录面板中查看当前书的所有书签 | 无独立导出；可通过共享表单分享笔记 | 自动保存阅读位置，书签需手动添加 |
| **掌阅 iReader** | 阅读页工具栏点击书签图标添加 | 无分类，仅支持删除 | 书签列表查看 | 支持导出笔记为 TXT/PDF；可同步到印象笔记/有道云 | 书签与笔记绑定导出，无纯书签导出 |
| **多看阅读** | 长按文本添加书签 | 无分类 | 快捷书签功能 | 笔记可分享至微博、印象笔记；跨设备云同步 | 云同步是亮点，书签管理简单 |
| **豆瓣阅读** | 阅读中批注、划线、添加书签 | 无分类 | 无独立书签页 | 无导出功能 | 侧重社区互动，书签功能薄弱 |

**对比总结**：
- 主流阅读器书签功能普遍简单：手动添加、按书籍组织、无分类标签、导出能力弱
- 书签通常与笔记/标注混合管理，少有独立书签系统
- 导出功能普遍依赖第三方工具，原生支持差
- 云同步是高端阅读器的标配（微信读书、多看、Apple Books）

## 3. 书签添加

### 3.1 手动添加（核心方式）

在阅读页面提供明确的书签添加入口：

**触发方式**：
- 点击屏幕中央呼出工具栏 → 点击书签图标
- 长按经文段落 → 弹出菜单含"添加书签"选项

**数据结构**：
```javascript
{
  id: 'bm::xin-jing::0::50',      // 自动生成
  sutraId: 'xin-jing',             // 经书 ID
  chapter: 0,                      // 章节索引
  position: 50,                    // 字符偏移位置
  context: '观自在菩萨，行深般若...',  // 前后文摘要（约50字）
  note: '',                        // 用户备注（可选）
  createdAt: '2026-05-02T10:00:00Z'
}
```

### 3.2 自动书签（阅读进度）

每次退出阅读页时，自动保存当前阅读位置作为"隐式书签"：

- 不展示在书签列表中，仅用于"继续阅读"功能
- 与 `reading_progress` 表共用，不额外创建书签记录
- 用户重新打开同一部经书时，自动跳转到上次位置

### 3.3 不做：自动批量生成

- 不在章节切换时自动添加书签（避免产生过多无用书签）
- 不在 TTS 暂停时自动添加（与阅读进度功能重复）

## 4. 书签管理

### 4.1 书签列表展示

**入口**：书架页面顶部或侧边栏添加"书签"入口，阅读页工具栏也可进入。

**展示形式**：

```
┌──────────────────────────────────────┐
│  我的书签                        [筛选]│
├──────────────────────────────────────┤
│                                      │
│  📖 心经                             │
│  ├─ 观自在菩萨，行深般若波罗蜜多时... │
│  │  第1章 · 2026-05-02              │
│  │  [跳转] [编辑] [删除]             │
│  ├─ 舍利子，色不异空，空不异色...    │
│  │  第1章 · 2026-05-01              │
│  │  [跳转] [编辑] [删除]             │
│                                      │
│  📖 金刚经                           │
│  ├─ 如是我闻，一时佛在舍卫国...     │
│  │  第1章 · 2026-04-30              │
│  │  [跳转] [编辑] [删除]             │
│                                      │
├──────────────────────────────────────┤
│  共 3 个书签                         │
└──────────────────────────────────────┘
```

**排序**：默认按创建时间倒序（最新的在最上面），可按经书分组查看。

### 4.2 分类和标签

**决策：v2.0 不做分类和标签**

理由：
1. 佛经阅读场景中，书签数量通常较少（一部经书几个到十几个书签）
2. 按经书分组已足够组织书签
3. 分类标签会增加交互复杂度，违背"简单、不打扰"理念
4. 主流阅读器（微信读书、Kindle、Apple Books）均无书签分类功能

**未来扩展**（v2.1+）：
- 如书签数量增长，可考虑添加"收藏夹"或"标签"功能
- 数据模型已预留 `tags` 字段，后续可启用

### 4.3 检索

**v2.0 支持的检索方式**：
- 按经书筛选：下拉选择经书，仅显示该书书签
- 全文搜索：输入关键词，搜索书签的 `context` 和 `note` 字段

**不做的**：
- 按时间范围筛选（书签总量少时不需要）
- 按标签筛选（v2.0 无标签功能）

### 4.4 书签操作

| 操作 | 说明 |
|------|------|
| **跳转** | 点击后打开对应经书，跳转到标记位置 |
| **编辑** | 修改备注文字（note 字段） |
| **删除** | 单个删除，需二次确认 |
| **批量删除** | 多选后批量删除（长按进入选择模式） |

## 5. 导出和导入

### 5.1 导出

**导出格式**：JSON + TXT 双格式

**JSON 格式（完整数据，用于备份恢复）**：
```json
{
  "version": "1.0",
  "exportedAt": "2026-05-02T10:00:00Z",
  "bookmarks": [
    {
      "sutraId": "xin-jing",
      "sutraTitle": "心经",
      "chapter": 0,
      "position": 50,
      "context": "观自在菩萨，行深般若...",
      "note": "这段很重要",
      "createdAt": "2026-05-02T10:00:00Z"
    }
  ]
}
```

**TXT 格式（纯文本，方便阅读和分享）**：
```
般若书签导出 - 2026-05-02
========================

【心经】
- 观自在菩萨，行深般若波罗蜜多时...
  备注：这段很重要
  时间：2026-05-02

- 舍利子，色不异空，空不异色...
  时间：2026-05-01

【金刚经】
- 如是我闻，一时佛在舍卫国...
  时间：2026-04-30
```

**导出方式**：
- 书签列表页提供"导出"按钮
- 可选择导出全部或选中部分
- 导出为文件下载（浏览器 download API）

### 5.2 导入

**导入流程**：
1. 书签管理页提供"导入"按钮
2. 选择之前导出的 JSON 文件
3. 解析文件，预览导入内容（显示将导入的书签数量）
4. 确认导入，合并到现有书签（按 ID 去重，避免重复导入）

**冲突处理**：
- 相同 ID 的书签：跳过（保留已有版本）
- 不同 ID 但相同位置的书签：都保留（可能备注不同）

### 5.3 云同步（远期）

v2.0 不支持云同步，但数据模型预留扩展：

- `bookmarks` 表可添加 `synced` 字段标记同步状态
- 未来可对接后端 API 实现多设备同步
- 当前所有数据存储在 IndexedDB 本地

## 6. 结论与建议

### 6.1 书签功能方案

| 维度 | 决策 | 理由 |
|------|------|------|
| 添加方式 | 手动添加（工具栏 + 长按菜单） | 简洁明确，符合用户习惯 |
| 自动书签 | 仅保存阅读进度，不作为书签展示 | 避免产生大量无意义书签 |
| 分类标签 | v2.0 不做 | 书签数量少，按经书分组已足够 |
| 检索 | 按经书筛选 + 全文搜索 | 覆盖核心使用场景 |
| 导出 | JSON + TXT 双格式 | JSON 用于备份恢复，TXT 用于阅读分享 |
| 导入 | JSON 文件导入，预览确认后合并 | 数据安全，避免重复 |
| 云同步 | v2.0 不做 | 纯前端优先，预留后端接口 |

### 6.2 数据模型

在 v2.0 方案已有 `bookmarks` 表基础上完善：

```
Table: bookmarks
┌──────────────────────┬──────────────┬──────────┬─────────────┬──────────┬──────────┬──────────┬──────────────┐
| id (PK)              | sutra_id     | chapter  | position    | context  | note     | tags     | created_at   |
├──────────────────────┼──────────────┼──────────┼─────────────┼──────────┼──────────┼──────────┼──────────────┤
| bm::001              | xin-jing     | 0        | 50          | 观自在...| 重要段落| []       | 2026-05-02   |
└──────────────────────┴──────────────┴──────────┴─────────────┴──────────┴──────────┴──────────┴──────────────┘

索引：
- idx_sutra: (sutra_id)          — 按经书查询
- idx_created: (created_at DESC) — 按时间排序
```

### 6.3 新增 Service 接口

```javascript
class BookmarkService {
  // 添加书签
  async addBookmark(sutraId, chapter, position, context, note)

  // 获取单部经书的所有书签
  async getBookmarksBySutra(sutraId)

  // 获取所有书签（按时间倒序）
  async getAllBookmarks()

  // 更新书签备注
  async updateBookmark(id, note)

  // 删除书签
  async deleteBookmark(id)

  // 批量删除
  async deleteBookmarks(ids)

  // 搜索书签（按经书和关键词）
  async searchBookmarks(sutraId, keyword)

  // 导出为 JSON
  async exportBookmarks(ids)

  // 导入 JSON 数据
  async importBookmarks(jsonData)
}
```

## 7. 对 v2.1 方案的影响

1. **数据模型扩展预留**：`bookmarks` 表已预留 `tags` 和 `synced` 字段，v2.1 如需添加标签和云同步功能可直接启用，无需修改表结构。

2. **Service 接口标准化**：BookmarkService 的设计与项目已有的 DictService、SutraService 风格一致，符合"接口预留、可切换后端 API"的架构原则。v2.1 若需对接后端，只需替换 Storage 层实现。

3. **UI 组件复用**：书签列表页的展示模式（按经书分组、上下文预览、操作按钮）可复用于未来的笔记功能设计，减少重复开发。

4. **导出/导入框架通用化**：书签的导出导入逻辑（JSON 序列化 + TXT 格式化 + 冲突处理）可抽象为通用工具模块，未来笔记、阅读进度等功能可复用。

5. **Phase 3 工作量评估**：书签功能预估 4h 工时合理，具体拆解为：
   - BookmarkService + bookmarkStore 实现：1.5h
   - 书签添加 UI（阅读页工具栏 + 长按菜单）：0.5h
   - 书签列表页 + 检索：1h
   - 导出/导入功能：0.5h
   - 测试和调试：0.5h

6. **与笔记功能的关系**：书签是笔记功能的前置基础。建议 v2.1 规划笔记功能时复用书签的数据模型（同一张表或关联表），共享列表展示和导出导入逻辑。
