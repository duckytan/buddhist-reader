## 1. 验收概述

### 1.1 验收目的

确认般若佛经阅读器 v2.0 的功能、性能、安全性和用户体验符合需求规格说明书中定义的标准，达到可发布至生产环境的条件。

### 1.2 验收范围

| 范围 | 说明 |
|------|------|
| 功能验收 | 5 个核心页面的所有功能需求 |
| 非功能验收 | 性能指标、安全要求、兼容性、用户体验 |
| 数据验收 | IndexedDB 数据完整性、迁移正确性 |
| 部署验收 | Vercel 部署成功、域名可访问 |

### 1.3 验收环境

| 环境 | 配置 |
|------|------|
| 生产预览 | Vercel Preview Deployment |
| 浏览器 | Chrome 最新版（桌面） |
| 网络 | 标准 4G 网络（Lighthouse  throttling） |
| 设备 | iPhone 12 Safari（移动端验证） |

### 1.4 参与方

| 角色 | 职责 |
|------|------|
| 验收方（产品负责人） | 执行验收测试、确认验收结果 |
| 开发方 | 修复验收中发现的问题、提供技术支持 |
| 测试方 | 提供自动化测试报告、性能数据 |

## 2. 验收标准

### 2.1 功能验收通过标准

| 级别 | 标准 |
|------|------|
| 通过 | 所有 P0 功能项通过，P1 功能项通过率 >= 95%，无 P0/P1 级别缺陷 |
| 有条件通过 | P0 功能项全部通过，P1 功能项通过率 >= 85%，遗留问题有明确修复计划 |
| 不通过 | P0 功能项有未通过项，或 P1 功能项通过率 < 85% |

### 2.2 非功能验收通过标准

| 类别 | 通过标准 |
|------|----------|
| 性能 | 全部性能指标达到目标值（允许 5% 偏差） |
| 安全 | 全部安全测试用例通过，无中高危漏洞 |
| 兼容性 | P0 浏览器全部通过，P1 浏览器无阻塞性 Bug |
| 用户体验 | 禅意设计系统规范 100% 遵循，无明显视觉缺陷 |

### 2.3 缺陷严重等级

| 等级 | 定义 | 验收影响 |
|------|------|----------|
| P0 - 致命 | 核心功能不可用、数据丢失、安全漏洞 | 阻断验收 |
| P1 - 严重 | 主要功能异常、性能严重不达标 | 必须修复后验收 |
| P2 - 一般 | 次要功能异常、UI 轻微不一致 | 可带条件验收 |
| P3 - 轻微 | 文字错误、小图标偏移 | 不影响验收 |

使用 Lighthouse 在生产预览 URL 上执行 3 次测试，取平均值。

| 指标 | 目标值 | 测量工具 | 验收方法 |
|------|--------|----------|----------|
| FCP | < 1s | Lighthouse | 3 次测试平均值 < 1s |
| LCP | < 2.5s | Lighthouse | 3 次测试平均值 < 2.5s |
| TTI | < 3.5s | Lighthouse | 3 次测试平均值 < 3.5s |
| JS Bundle | < 150KB | rollup-plugin-visualizer | 构建报告中检查 |
| CSS Bundle | < 30KB | rollup-plugin-visualizer | 构建报告中检查 |
| 高亮响应 (5000 字) | < 30ms | Chrome DevTools | 5 次测试平均值 < 30ms |
| 释义加载 | < 200ms | Chrome DevTools | 5 次测试平均值 < 200ms |
| 内存 (5 个词典) | < 50MB | Chrome DevTools Memory | 单次检查 < 50MB |

| CSP 策略 | 检查响应头 | Content-Security-Policy 正确配置 |

## 5. 验收流程

### 5.1 验收准备

```mermaid
graph LR
    A["开发方提交构建产物"] --> B["部署至 Vercel Preview"]
    B --> C["提供测试报告和性能数据"]
    C --> D["验收方准备验收环境"]
    D --> E["开始验收测试"]
```

1. 开发方完成全部功能开发和自测
2. 代码合入主分支，触发 Vercel 自动部署
3. 开发方提供测试报告（自动化测试通过率、性能数据）
4. 验收方确认测试报告达标后开始验收

### 5.2 验收执行

1. **功能验收**：按照第 3 节验收用例逐一执行，记录结果
2. **非功能验收**：按照第 4 节执行性能、安全、兼容性、UX 验收
3. **缺陷记录**：发现的问题记录至缺陷清单，标注严重等级
4. **缺陷修复**：开发方修复 P0/P1 缺陷，重新部署后回归验收

### 5.3 验收结论

| 结论 | 条件 |
|------|------|
| 通过 | 满足 2.1 和 2.2 全部通过标准 |
| 有条件通过 | 满足通过标准，遗留 P2 缺陷有修复计划 |
| 不通过 | 存在 P0 未通过项或 P1 通过率不达标 |
