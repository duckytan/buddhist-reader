## 二、详细设计

### 2.1 Trie 索引层

**数据结构**（轻量索引）：

```
dict_index 表:
+--------+---------+---------+-----------+---------+
| term   | dict_id | pinyin  | category  | has_def |
+--------+---------+---------+-----------+---------+
| 般若   | builtin | bō rě  | 核心术语  | 1       |
| 般若   | user-001| bō rě  |           | 1       |
+--------+---------+---------+-----------+---------+
```

Trie 匹配后返回：`[{ term, start, end, dictId, pinyin, category }]`

**构建时机**：每次启动从 `dict_index` 读 term 列表重建，不持久化 Trie 本身。

**组织策略**：单一 Trie 存所有词典词条，搜索后通过 `enabledDictIds` 集合运行时过滤。接口设计时 Trie 层与搜索层解耦，未来可平滑切换为分层 Trie（每个词典独立 Trie，分别搜索后合并）。

### 2.2 MDX 词典导入与切割

**流程**：

```
用户上传 .mdx → 用 mdict-js 预解析为 JSON → 按规则切割 → 存入 IndexedDB
```

**切割规则**：

- 单文件上限 10MB（指原始 .mdx 文件，非解析后大小）
- 解析后数据按 **2MB/块** 切割（逐条累加，接近上限时切块）
- 单条释义超 2MB 则单独成块
- 生成 `chunk_manifest` 记录分片信息
- 生成 `dict_term_lookup` 路由表：`term + dict_id → chunk_id`

**存储结构**：

```
dict_chunks (分片元数据):
+-------------+---------+----------+----------+----------+
| chunk_id    | dict_id | chunk_no | size     | term_cnt |
+-------------+---------+----------+----------+----------+
| user-001:0  | user-001| 0        | 1.8MB    | 2340     |
| user-001:1  | user-001| 1        | 1.9MB    | 1890     |
+-------------+---------+----------+----------+----------+

dict_entries (释义数据，按 chunk 分组存储):
+------------------+-----------+--------+-------------+-----------+
| key              | chunk_id  | term   | definition  | category  |
+------------------+-----------+--------+-------------+-----------+
| user-001::般若   | user-001:0| 般若   | ## 般若\n... |           |
+------------------+-----------+--------+-------------+-----------+

dict_term_lookup (路由表):
+--------+---------+-----------+
| term   | dict_id | chunk_id  |
+--------+---------+-----------+
| 般若   | user-001| user-001:0|
+--------+---------+-----------+
```

**查询路径**：`term 匹配 → dict_term_lookup 找 chunk_id → dict_entries 查释义`，两步均走索引，总开销 < 2ms。

### 2.3 多词典释义展示

**加载策略**：流式加载（streaming）。点击术语后并行查询所有启用词典，先返回的先渲染。

**3 种展示模式**（IndexedDB settings 表存储，下次自动恢复）：

| 模式 | 行为 |
|------|------|
| **全部折叠** | 并行查完所有词典后统一展示，列出词典名，点击展开释义 |
| **展开第一个，其余折叠**（默认） | 第一个词典释义流式加载直接渲染，其余查完后折叠追加为"另有 N 个释义" |
| **全部展开** | 所有词典释义流式加载，逐个追加展开 |

### 2.4 释义格式

**存储格式**：统一 Markdown。

**渲染引擎**：`markdown-it`，开启 `html: true`，允许 HTML 标签直通。

**特殊格式处理**：梵文/藏文/Pali 文用内联 HTML 保留 class 信息：

```markdown
## 般若

梵语 <span class="sanskrit">prajñā</span> 的音译，意为"智慧"。
```

**MDX 导入**：使用 `turndown` 将 HTML 释义转 Markdown，存入 `dict_entries`。

**用户笔记**：同样存 Markdown，渲染时与原文 Markdown 拼接后统一通过 markdown-it 渲染。
