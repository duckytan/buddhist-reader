# v3.0 架构设计文档

> 般若佛经阅读器 v3.0 — 禅意极简风格，点击即查释义
> 日期：2026-05-03

## 1. 项目定位

**核心目的**：让用户在阅读经书时，遇到晦涩术语可点击即查释义，无需翻阅专业词典。

**参考体验**：小说阅读 APP（字体、主题、书签、目录、搜索、笔记）。

**设计原则**：禅意极简 — 宣纸色背景、墨色文字、零阴影。

---

## 2. 功能范围（v3.0 第一版）

### 2.1 书架页面
- 经书列表（卡片式，显示标题、作者、分类、字数）
- 分类筛选（般若/唯识/禅宗/密咒/通论/传记）
- 点击经书进入阅读

### 2.2 阅读页面
- **连续滚动**阅读（非分页）
- **进度条**显示当前阅读位置
- **目录跳转**（章节列表，点击跳转）
- **字体大小**调整（小/中/大/特大）
- **行间距**调整（紧凑/舒适/宽松）
- **背景色/主题**切换（日间/夜间/护眼/宣纸）
- **书签/阅读进度**自动保存（localStorage）
- **搜索全文**（当前经书内搜索关键词）
- **阅读时长统计**
- **笔记/批注**（选中文字添加笔记）

### 2.3 词典系统（核心）
- **自动高亮**：经文中的佛学术语自动高亮显示
- **点击查释义**：点击高亮词，底部弹出释义面板
- **长按选词查**：长按任意文字，选中后查释义
- **多词典并行查询**：同时查询 3 部词典，先返回先显示
- **词典管理**：启用/禁用某部词典

## 3. 技术架构

### 3.1 技术栈

| 层 | 技术 | 说明 |
|----|------|------|
| 框架 | Vue 3 + Composition API | 响应式组件化 |
| 构建 | Vite 5 | 快速冷启动 |
| UI | 纯手写组件 | 不用 Vant，完全掌控样式 |
| 状态 | Pinia | 职责单一的 Store |
| 路由 | Vue Router 4 | SPA 路由 |
| 存储 | localStorage | 阅读进度、设置、书签 |
| 词典 | 懒加载 | 索引在线 + 释义按需 fetch |

## 4. 数据流设计

### 4.1 经书加载流程

```
用户点击经书
  → router 跳转到 /reader/:id
  → Reader.vue 挂载
  → useSutraLoader(id) 开始加载
    → fetch(/sutras/manifest.json) 获取经书元数据
    → fetch(/sutras/{filename}.json) 获取经书内容
    → sutraStore 更新当前经书
  → ReaderContent.vue 渲染经文
    → useHighlighter(content, dictIndex) 高亮术语
    → 用户看到带高亮的经文
```

### 4.2 词典查询流程（核心）

```
启动时：
  → fetch(/dicts/manifest.json) 获取词典列表
  → 并行 fetch 每部词典的前 N 条（或只 fetch 索引）
  → dictStore 构建词条索引（Set/Map）
  → ReaderContent 用索引高亮经文中的术语

点击高亮词时：
  → readerStore 记录选中的词
  → DictPopup 组件显示
  → 并行 fetch 启用的词典 JSON 文件
    → 在内存中查找该词条
    → 先找到先显示（流式）
  → 多词典结果合并显示

长按选词时：
  → 浏览器原生选中文本
  → 显示"查释义"浮动按钮
  → 点击后走同上流程
```

### 4.3 阅读进度保存

```
滚动时（节流 500ms）：
  → readerStore 更新 scrollPosition
  → localStorage.setItem('reading-progress', { sutraId, chapter, position })

重新打开经书时：
  → 从 localStorage 读取进度
  → 自动滚动到上次位置
```

## 5. 词典索引策略

### 5.1 索引格式

启动时加载的索引是一个简单的对象：

```javascript
// dictIndex.js (generated at build time)
export const dictIndex = {
  "般若": ["dict-1", "dict-2"],      // 哪些词典包含这个词
  "波罗蜜多": ["dict-1"],
  "菩提": ["dict-1", "dict-2", "dict-3"],
  // ... 35781 entries
}
```

生成方式：构建时扫描 `public/dicts/*.json`，提取所有 `term`，生成 `dictIndex.js`。

### 5.2 高亮逻辑

```javascript
// useHighlighter.js
function highlightText(content, dictIndex) {
  // 遍历 dictIndex 的所有词条
  // 在 content 中查找匹配
  // 用 <span class="dict-highlight" data-term="xxx">包裹</span>
  // 注意：长词优先（先匹配"般若波罗蜜多"再匹配"般若"）
}
```

### 5.3 释义查询

```javascript
// 点击时
async function lookupTerm(term) {
  const dictIds = dictIndex[term] || []
  const results = []
  
  for (const dictId of dictIds) {
    const dict = await fetchDict(dictId)  // 按需 fetch
    const entry = dict.entries.find(e => e.term === term)
    if (entry) results.push({ dictId, ...entry })
  }
  
  return results
}
```

## 8. 性能策略

### 8.1 启动性能
- 索引预生成：构建时生成 `dictIndex.js`，避免运行时扫描
- 代码分割：路由懒加载，书架和阅读页面分开打包
- 字体优化：使用系统字体栈，不加载外部字体

### 8.2 运行时性能
- 滚动节流：滚动事件节流 100ms
- 高亮优化：只在可视区域高亮，或虚拟滚动
- 词典缓存：fetch 的词典 JSON 缓存到内存，5 分钟过期
- 图片懒加载：书架卡片图片懒加载

### 8.3 内存管理
- 离开阅读页面时释放词典缓存
- 索引常驻内存（~1MB），释义按需加载

## 9. 错误处理

| 场景 | 处理 |
|------|------|
| 经书加载失败 | 显示"加载失败，点击重试" |
| 词典加载失败 | 禁用该词典，提示用户 |
| 词条未找到 | 显示"暂无释义" |
| 网络断开 | 显示离线提示，允许阅读已加载内容 |

## 12. 关键决策总结

| 决策 | 选择 | 理由 |
|------|------|------|
| UI 组件库 | 纯手写 | 完全掌控禅意样式，不用覆盖 Vant |
| 阅读方式 | 连续滚动 | 体验更自然，像小说 APP |
| 词典加载 | 索引在线 + 释义按需 | 启动快、内存省 |
| 状态管理 | Pinia 职责单一 | 避免 v2.0 Store 交叉问题 |
| 存储 | localStorage | 简单可靠，无需 IndexedDB |
| 主题 | CSS 变量 + data-theme | 切换无闪烁，性能好 |
| 高亮 | 构建时生成索引 | 运行时只需查找，无需扫描 |
