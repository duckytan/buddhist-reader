# 词典管理系统设计 分析报告

> 任务编号：T-18
> 完成日期：2026-05-02
> 基于：docs/PROJECT_V2_PLAN.md, docs/DICTIONARY_OPTIMIZATION_DISCUSSION.md

## 1. 背景与目标

般若佛经阅读器 v2.0 需要建设一个完整的词典管理页面，作为用户管理词典的核心入口。v1.0 中词典为硬编码，无管理入口；v2.0 支持内置词典 + 用户上传词典（JSON/CSV/MDX），需提供列表展示、开关控制、导入导出、版本管理等全生命周期管理功能。

核心目标：
- 提供清晰的词典列表视图，支持开关切换、批量操作
- 实现平滑的词典导入流程，支持多种格式和错误处理
- 开关切换后高亮立即生效（D7），并显示受影响词条数（D12）
- 版本链管理（D14），支持回滚和历史查看
- 移动端优先，符合 Vant 4 组件规范

## 2. 词典列表设计

### 2.1 展示方式

采用 Vant Cell 卡片列表 + 分组展示，每个词典占一行。

| 字段 | 展示方式 | 说明 |
|------|----------|------|
| 名称 | 左侧图标 + 标题文字 | 内置词典显示 "📖 内置词典"，用户上传显示 "📁 文件名" |

### 2.2 排序和筛选

**排序规则**：
1. 分组优先：官方词典组在前，个人词典组在后

## 3. 开关交互设计

### 3.1 开关切换流程

**事件时序图**：

```
用户滑动开关
    │
    ▼
[UI 层] 开关立即切换视觉状态 (Vant Switch 动画 ~200ms)
    │
    ├── 如果关闭：显示受影响词条数提示（底部 Toast 或折叠面板）
    │
    ▼
[Store 层] dictStore.toggleDict(dictId, newEnabled)
    │
    ▼
[Storage 层] 写入 IndexedDB dict_config 表 (持久化)
    │
    ├── 成功
    │   ▼
    │   [Engine 层] TrieManager.enable/disable(dictId)
    │       │
    │       ▼
    │       更新 enabledDictIds 集合
    │       │
    │       ▼
    │       通知阅读页高亮引擎重新扫描
    │           │
    │           ▼
    │           高亮刷新 (D7 立即生效)
    │
    └── 失败
        ▼
        [UI 层] 开关回滚到原状态 + Toast 错误提示
```

**关键设计决策**：
- 开关切换采用"乐观更新"策略：先改 UI，再写数据库，失败回滚
- D4 决策采用"懒标记"方案：开关切换不重建 Trie，仅改变 `enabledDictIds`
- D7 决策"立即生效"：切换后通过事件总线通知阅读页重新渲染高亮
- 所有开关状态在 IndexedDB `dict_config` 表中持久化

### 3.2 受影响词条数计算

**计算逻辑**：

```javascript
// 关闭词典时，计算该词典独有词条数（其他启用词典不覆盖的词条）
async function calcAffectedEntries(dictId) {
  const currentDictTerms = await getTermsByDictId(dictId)
  const otherEnabledDictIds = getEnabledDictIds().filter(id => id !== dictId)

  let affectedCount = 0
  for (const term of currentDictTerms) {
    // 检查该词条是否也被其他已启用词典覆盖
    const coveredByOthers = await isTermCoveredByDicts(term, otherEnabledDictIds)
    if (!coveredByOthers) {
      affectedCount++
    }
  }
  return affectedCount
}
```

**显示策略**：
- 关闭时：在开关下方以 Vant NoticeBar 或折叠面板显示
  - "关闭后将少高亮 **X** 个词条"
  - 如果 X = 0：显示"该词典的所有词条已被其他词典覆盖"
- 打开时：不需要额外提示（D9 新词典默认开启）
- 数值预计算：在词典导入时预计算并缓存 `uniqueTermCount`，避免每次开关时实时计算

**移动端优化**：
- 使用折叠面板（Vant Collapse）而非弹窗，避免打断用户操作流
- 受影响词条数以橙色/红色文字高亮

### 3.3 全部启用/禁用

**设计**：
- 页面顶部放置两个按钮：[全部启用] [全部禁用]
- 内置词典不可被"全部禁用"关闭（至少保留一个启用词典，否则 D8 高亮功能关闭）
- 点击"全部禁用"时，弹出 Vant Dialog 确认：
  - 标题："确认全部禁用？"
  - 内容："禁用后经文将不再高亮任何词条"
  - 按钮：[取消] [确认禁用]
- 执行时：批量更新 IndexedDB，触发一次 TrieManager 重建
- 显示进度：使用 Vant Loading 或 Toast 提示"正在更新..."

**批量操作时序**：

```
用户点击 [全部禁用]
    │
    ▼
Dialog 确认 → 用户确认
    │
    ▼
显示 Toast "正在更新..."
    │
    ▼
批量写入 IndexedDB dict_config 表（事务）
    │
    ▼
TrieManager 重建（清空所有 Trie，仅保留内置）
    │
    ▼
通知阅读页刷新高亮
    │
    ▼
关闭 Toast，更新列表 UI
```

## 4. 文件导入设计

### 4.1 支持格式

| 格式 | 处理方式 | 验证规则 |
|------|----------|----------|
| **JSON** | 解析为数组/对象，统一转为标准格式后存入 IndexedDB | 必须是合法 JSON；必须包含 `term` 和 `definition` 字段；支持数组 `[{term, definition}]` 或对象 `{"term": "definition"}` 两种结构 |
| **CSV** | 按行解析，首行作为表头映射字段 | 必须包含 `term` 列；支持 UTF-8 编码；分隔符支持 `,`、`;`、`\t` 自动检测；最大 10 万行 |
| **MDX** | 小文件（<5MB）预解析为 JSON 存入 IndexedDB；大文件（>=5MB）保留原文件用 mdict-js 实时查询 | 必须是有效 MDict 格式；检查文件头标识（`0x00000000` 或 `MDEX`）；同名 .mdd 资源文件可选关联 |

**格式自动检测**：
1. 通过文件扩展名初步判断（`.json`、`.csv`、`.mdx`）
2. 无扩展名时读取文件前 256 字节进行内容嗅探：
   - JSON：以 `{` 或 `[` 开头
   - CSV：首行包含逗号/分号/制表符分隔的文本
   - MDX：检查 MDict 文件头魔数

### 4.4 回滚机制

**导入失败时的回滚策略**：

```javascript
async function importDict(file) {
  const snapshot = await createRollbackSnapshot()

  try {
    // 步骤 1-7: 导入流程
    await parseAndImport(file)
  } catch (error) {
    // 回滚：删除新创建的记录
    await rollbackToSnapshot(snapshot)

    // 通知用户
    showDialog({
      title: '导入失败',
      message: `原因：${error.message}\n\n已回滚到导入前状态，数据未受影响。`,
      confirmButtonText: '我知道了'
    })
    return
  }
}
```

**回滚点设计**：
1. 解析前快照：记录当前所有词典 ID 列表
2. 写入前快照：如果同名词典已存在，记录其当前版本
3. 回滚操作：
   - 删除新创建的 `dict_config` 记录
   - 删除新写入的 `dict_index` 条目
   - 删除新写入的 `dict_entries` 条目
   - 删除缓存的 .mdx 文件
   - 恢复旧版本（如果是覆盖导入）

**关键保障**：
- IndexedDB 事务保证原子性：整个写入过程在一个事务中，任一失败自动回滚
- 预校验阶段在写入之前完成，最大程度减少失败概率
- 回滚操作本身不会失败（仅执行删除操作）

### 5.2 回滚操作

**回滚流程**：

```
用户点击 [回滚到此]
    │
    ▼
Vant Dialog 确认
    标题："确认回滚到版本 X？"
    内容："当前版本 X 将被保留为历史版本，回滚后版本 Y 将成为当前版本。"
    按钮：[取消] [确认回滚]
    │
    ▼
复制目标版本的 dict_index 和 dict_entries 到新版本记录
    │
    ▼
更新 dict_config 的 version 字段
    │
    ▼
重建 Trie 索引
    │
    ▼
Toast："已回滚到版本 X"
    │
    ▼
刷新列表，阅读页高亮自动更新
```

**设计要点**：
- 回滚不删除任何历史版本，仅创建新快照指向旧数据
- 回滚后版本号递增（版本 4 = 版本 2 的快照）
- 用户笔记层（D10）与版本分离：回滚不影响用户笔记

### 5.4 删除词典

**删除流程**：

```
用户点击词典项的删除按钮
    │
    ▼

    标题："确认删除词典？"

    │
    ▼
校验输入内容是否匹配词典名称
    │
    ▼

    - 删除 dict_config 记录
    - 删除 dict_index 中该词典的所有条目
    - 删除 dict_entries 中该词典的所有条目
    - 删除 dict_versions 中该词典的所有版本

```

**二次验证设计理由**：
- 删除操作不可逆，需要最高级别的确认
- 要求输入词典名称可防止误触
- 显示将删除的数据量（版本数、词条数）让用户充分了解后果

| **导入方式** | 文件夹扫描（指定目录，自动识别） | 桌面端拖拽导入；移动端手动放置文件到指定目录 | 应用内 Uploader 选择文件导入 |
| **词典管理** | 右键菜单分组管理，勾选启用/禁用，排序调整 | 设置页词典管理列表，开关切换，拖拽排序优先级 | Vant 列表 + Switch，分组展示，排序筛选 |
| **开关切换** | 勾选复选框，即时生效 | 滑动开关，即时生效 | 滑动开关，乐观更新，立即生效（D7） |
| **版本管理** | 无（覆盖原文件即更新） | 无（覆盖原文件即更新） | 版本链（D14），支持回滚和历史查看 |
| **导入校验** | 文件格式检查，自动识别 | 文件格式 + 完整性检查（MDX 头标识） | 格式校验 + 字段验证 + 体检报告（D11） |
| **进度显示** | 无（后台扫描） | 进度条（拖拽导入时） | 分步进度条，支持取消 |
| **重复处理** | 同名词典重复添加（用户手动管理） | 同名覆盖提示 | 自动创建新版本（D14） |
| **词条统计** | 词典信息中显示词条数 | 词典管理中显示词条数 | 列表显示词条数 + 开关时显示受影响词条数（D12） |
| **词典分组** | 支持（按语言/主题创建分组） | 支持（在线词库下载分类） | 按类型分组（官方/个人） |
| **移动端适配** | 有（Android 版） | 有（iOS/Android） | H5 响应式（手机/平板/PC） |
| **离线使用** | 完全离线 | 离线词典 + 在线扩展 | 完全离线（纯前端 IndexedDB） |

**本项目差异化优势**：
1. **版本链管理**：GoldenDict 和欧路词典均不支持版本管理，本项目首创版本链 + 回滚
2. **开关影响反馈**：唯一提供"少高亮 X 个词条"的即时反馈
3. **体检报告**：导入前自动分析词典质量，同类软件均无此功能
4. **纯前端离线**：不依赖任何后端服务，数据完全本地化

## 7. 结论与建议

### 7.1 推荐的词典管理设计方案

**核心架构**：
- 使用 Vant 4 的 Cell、Switch、Dialog、Progress、Uploader 组件构建管理页面
- 分层 Trie 架构（PROJECT_V2_PLAN 4.2.1）配合懒标记（D4）实现开关即时响应
- IndexedDB 事务保证导入/删除操作的原子性
- 版本链基于 `dict_versions` 表实现快照机制

**关键交互决策**：
1. **开关**：乐观更新 + 受影响词条数提示 + IndexedDB 持久化
2. **导入**：选择文件 → 验证 → 解析 → 体检报告 → 用户确认 → 写入 → 构建 Trie → 完成
3. **版本**：同名词典重复上传自动创建新版本，不覆盖；支持回滚但不删除历史
4. **删除**：二次验证（输入名称确认）+ 事务性删除 + Trie 注销

### 7.2 优先级建议

| 优先级 | 功能 | 理由 |
|--------|------|------|
| **P0** | 词典列表 + 开关 | 核心功能，无此无法管理词典 |
| **P0** | JSON/CSV 导入 | 用户自定义词典的最基本需求 |
| **P0** | 全部启用/禁用 | 批量操作，提升用户体验 |
| **P1** | MDX 导入 | 用户需求高，但依赖 mdict-js 解析复杂度较高 |
| **P1** | 体检报告 | 提升导入质量，但可以在基础导入后再加 |
| **P1** | 删除 + 二次确认 | 数据安全，但非首次使用必需 |
| **P2** | 版本历史 | D14 决策需要，但可作为后续迭代 |
| **P2** | 版本回滚 | 版本链的配套功能 |
| **P2** | 版本差异对比 | 高级功能，低频使用 |

### 7.3 技术风险提示

1. **大文件解析性能**：浏览器端解析 10MB+ 的 JSON/CSV 文件可能阻塞主线程，建议使用 Web Worker 或在分块读取时配合 `setTimeout` 释放主线程
2. **IndexedDB 批量写入性能**：10 万条词条批量写入需要分批次（每 1000 条一个事务），避免单次事务过大导致失败
3. **MDX 解析兼容性**：mdict-js 对部分非标准 MDX 文件可能存在解析问题，需要做好错误处理和降级方案
4. **移动端存储限制**：iOS Safari 对 IndexedDB 有 50MB-1GB 不等的限制（取决于设备），需要在导入前检查可用空间

## 8. 对 v2.1 方案的影响

本分析结果对 v2.1 及后续方案的影响：

1. **体检报告指标需要细化**（D11 未解决）：本报告提出了基础指标（词条总数、重复数、缺释义数），但 v2.1 需要明确：重复率阈值、格式异常的具体定义、与其他用户词典的冲突检测
2. **版本差异对比的实现方案**：v2.1 需要实现基于 `dict_index` 的 diff 算法，建议采用 Set 差集运算而非逐条比较，性能更优
3. **Web Worker 集成**：大文件解析建议放入 Web Worker，v2.1 需要在项目架构中增加 worker 目录和消息通信机制
4. **存储空间检查**：v2.1 需要实现 IndexedDB 存储配额检测（`navigator.storage.estimate()`），在导入前提示用户
5. **词典分享预留**（D22）：虽然词典分享/市场明确列入"不做清单"，但数据模型中的 `dict_config` 已预留 `sourceFile` 和 `mdxStrategy` 字段，v2.1 无需额外修改
