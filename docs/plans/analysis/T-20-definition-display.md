## 1. 背景与目标

般若佛经阅读器 v2.0 采用"点击高亮术语后按需加载释义"的架构（D1/D2 决策）。用户点击经文中的高亮词条后，需要从多个启用词典中并行查询释义，并在弹窗中展示。同时支持用户对词条添加个人笔记，笔记与原始释义分离存储（D10 决策）。

本分析聚焦以下核心问题：
- 释义弹窗的 UI/UX 设计（定位、流式加载、展示模式）
- 移动端适配策略
- Markdown 渲染质量保障
- 用户笔记层的设计（编辑器选型、搜索导出、版本历史）
- 笔记理念参考（Notion vs Obsidian）

## 2. 同类 App 对比

| 功能 | 欧路词典 (Eudic) | 有道词典 | 本项目需求 |
|------|------------------|----------|------------|
| **弹窗触发** | 跨软件取词：长按单词弹出悬浮窗释义；点击后弹窗显示解释（可配置） | 输入框查询后展示详细释义页 | 点击经文高亮词条，弹出释义卡片 |

| **多词典展示** | 左侧词典列表切换，结果页分栏展示基础释义、搭配、同义词、真题例句；支持调整词典优先级 | 底部多 Tab 切换（基本释义、网络释义、例句、百科）；收录多部权威词典数据 | 卡片式垂直堆叠，每卡片标注词典名称；流式追加渲染 |
| **展示模式** | 生词本支持一键全部展开/收起；解释界面可隐藏"发音和分组" | 查词界面优化，突出词根拓展、派生串记 | 全部折叠 / 展开首个 / 全部展开（3 种模式切换） |
| **笔记功能** | 每个词条可添加笔记，支持高亮标记、批注（录音/图片），云端同步；笔记可汇总显示高亮内容 | 单词本积累生词，但笔记功能较弱 | 每个释义卡片底部独立"添加笔记"按钮；笔记与原始释义分离存储 |
| **Markdown 支持** | 不支持，纯文本+HTML 渲染 | 不支持 | 释义和笔记均支持 Markdown（D15 决策） |
| **流式加载** | 不支持（本地词典一次性加载） | 网络释义需异步加载 | 多词典并行查询，先返回先渲染（6.3 建议流式加载） |
| **版本历史** | 词库支持版本更新和在线同步 | 不支持 | 笔记版本历史（需设计） |

### 欧路词典设计亮点（可借鉴）
1. **分栏展示**：基础释义、搭配短语、同义词辨析、真题例句分层展示，信息密度高但层级清晰
2. **一键展开/收起**：生词本支持一键全部展开/收起，减少信息过载
3. **自定义字体**：解释界面支持自定义字体，适配长时间阅读
4. **高亮笔记汇总**：笔记可汇总显示高亮内容，支持拖动设置分组层级

### 有道词典设计亮点（可借鉴）
1. **词根拓展**：突出词根拓展、派生串记，帮助学生理解词义关联
2. **网络释义**：独创网络释义，囊括流行词汇与海量例句

## 3. 弹窗设计

### 3.1 定位策略

#### PC / 平板（屏幕宽度 >= 768px）

采用**跟随高亮词条的浮动弹窗**方案：

```
┌─────────────────────────────────────────────┐
│  经文正文区域                                │
│                                             │
│  观自在菩萨，行深【般若】波罗蜜多时...       │
│                    ┌────────────────────┐    │
│                    │ 📖 内置词典         │    │
│                    │ 梵语 prajñā 的音译  │    │
│                    │ ...                │    │
│                    ├────────────────────┤    │
│                    │ 📚 中华佛教百科     │    │
│                    │ [加载中...]         │    │
│                    └────────────────────┘    │
│                                             │
│  照见五蕴皆空，度一切苦厄...                 │
└─────────────────────────────────────────────┘
```

**定位规则**：
- 弹窗顶部对齐高亮词条底部，左侧对齐词条起始位置
- 若弹窗超出右边界，则右对齐到视口右边缘
- 若弹窗超出下边界，则改为底部固定（fallback 为移动端模式）
- 最大宽度：420px；最大高度：60vh
- 带小三角指示器指向高亮词条
- 支持点击遮罩层或按 ESC 关闭

### 3.2 流式加载 UI

基于 6.3 决策（流式加载），采用**渐进式渲染**策略：

```

    ▼

│  核心术语                    │
│                              │
│  ┌────────────────────────┐ │
│  │ 📖 内置词典      ✅    │ │ ← 优先词典，同步或最快返回
│  │ 梵语 prajñā 的音译...  │ │
│  └────────────────────────┘ │
│                              │
│  ┌────────────────────────┐ │
│  │ 📚 中华佛教百科  ⏳    │ │ ← 加载中骨架屏
│  │ ░░░░░░░░░░░░░░░░░░░░░ │ │
│  └────────────────────────┘ │
│                              │
│  ┌────────────────────────┐ │
│  │ 📚 佛学大辞典    ⏳    │ │
│  │ ░░░░░░░░░░░░░░░░░░░░░ │ │
│  └────────────────────────┘ │
│                              │
│  [全部展开] [收起] [添加笔记] │
└──────────────────────────────┘
```

**加载状态反馈**：
| 状态 | UI 表现 | 动画 |
|------|---------|------|
| 初始 | 显示词条名、拼音、分类（来自 Trie 轻量索引） | 无 |
| 查询中 | 词典卡片显示骨架屏 + 旋转 loading 图标 | 脉冲动画 |
| 加载完成 | 骨架屏淡出，释义内容渐入 | fade-in 0.3s |
| 加载失败 | 卡片底部显示"加载失败，点击重试" | 红色边框 |
| 全部完成 | 移除所有 loading 状态 | 无 |

**防抖动设计**：
- 内容追加时保持当前滚动位置，避免页面跳动
- 使用 `scroll anchoring` 或记录 `scrollTop` 偏移量
- 每张卡片高度从骨架屏到真实内容的过渡使用平滑动画

### 3.3 展示模式

| 模式 | 适用场景 | 交互细节 | 图标 |
|------|----------|----------|------|
| **全部折叠** | 多词典（3+）时快速浏览词典来源 | 每张卡片仅显示词典名 + 摘要（前 20 字）+ 展开箭头；点击卡片展开 | `≡` 或 `▾` |
| **展开首个** | 默认模式，平衡信息量与简洁度 | 第一个词典完整展开，其余折叠显示摘要；支持一键展开全部 | `▾` |
| **全部展开** | 深度研读，对比多词典释义 | 所有词典卡片完整展开释义内容；长释义可单独折叠 | `▴` |

**模式切换交互**：
```
┌───────────────────────────────────────┐
│  般若  bō rě          [模式切换按钮 ▼]│
│                                       │
│  模式切换按钮为三段式开关：            │
│  [折叠 | 展开首个 | 全部展开]           │
│  或下拉菜单选择                        │
└───────────────────────────────────────┘
```

**默认策略**（与 D5 决策一致）：
- 默认"展开首个"模式
- 最高优先级词典（内置词典）始终排在第一位并展开
- 其余词典按用户设置的优先级排序，折叠显示"另有 N 个词典的释义"

## 4. Markdown 渲染

### 4.1 渲染库选型

| 库 | 包大小 (gzip) | 速度 | 扩展性 | XSS 防护 | 适用性 |
|----|---------------|------|--------|----------|--------|
| **marked** | ~8KB | 极快 (729 ops/s) | renderer 覆盖 | 需配合 DOMPurify | 推荐 |
| **markdown-it** | ~30KB | 快 (986 ops/s) | 插件系统丰富 | 需配合 DOMPurify | 备选 |
| **showdown** | ~12KB | 中等 | 扩展选项 | 需自行处理 | 不推荐 |

**推荐方案：marked + DOMPurify**

理由：
1. **体积最小**：8KB gzip，对移动端友好
2. **流式友好**：AI 对话场景推荐 marked，本项目流式加载同理
3. **内置 GFM**：表格、任务列表开箱即用
4. **零依赖**：集成成本极低
5. **DOMPurify 配合**：官方推荐的安全方案，防止 MDX 词典中的 HTML 注入

### 4.2 渲染质量要求

```javascript
// marked 配置
import { marked } from 'marked'
import DOMPurify from 'dompurify'

marked.setOptions({
  breaks: true,           // 换行符转 <br>
  gfm: true,              // GitHub 风格 Markdown
  headerIds: false,       // 不生成标题 ID（避免冲突）
  mangle: false,          // 不混淆邮箱地址
})

// 安全渲染
function renderMarkdown(text) {
  const rawHtml = marked.parse(text)
  return DOMPurify.sanitize(rawHtml, {
    ALLOWED_TAGS: ['p', 'br', 'strong', 'em', 'u', 'del', 'a', 'ul', 'ol', 'li',
      'h1', 'h2', 'h3', 'h4', 'h5', 'h6', 'blockquote', 'code', 'pre', 'table',
      'thead', 'tbody', 'tr', 'th', 'td', 'img', 'span', 'div', 'hr', 'sup', 'sub'],
    ALLOWED_ATTR: ['href', 'src', 'alt', 'title', 'class', 'id'],
  })
}
```

### 4.3 特殊格式处理

佛教经文释义中常见的特殊格式需求：

| 格式 | 处理方式 | 示例 |
|------|----------|------|
| **梵文** | 使用 `<span class="sanskrit">` 包裹，应用天城体字体 | `梵语 <span class="sanskrit">प्रज्ञा</span>` |
| **巴利文** | 使用 `<span class="pali">` 包裹 | `巴利语 <span class="pali">paññā</span>` |
| **藏文** | 使用 `<span class="tibetan">` 包裹，应用藏文字体 | `<span class="tibetan">ཤེས་རབ།</span>` |
| **音标** | 使用 `<ruby>` 标签 | `<ruby>般<rt>bō</rt></ruby>` |
| **引用** | blockquote 样式，左侧加竖线 | `> 原文引用...` |
| **重点词** | 加粗 + 高亮色 | `**核心概念**` |

## 5. 用户笔记设计

### 5.1 笔记与释义分离

基于 D10 决策（笔记层，不破坏原数据），采用**分层展示**方案：

```
┌────────────────────────────────────────┐
│  📖 内置词典                           │
│  ───────────────────────────────────── │
│  梵语 prajñā 的音译，意为"智慧"。      │
│  指超越世俗认识的究竟智慧...           │
│                                        │
│  ┌──────────────────────────────────┐ │
│  │ 📝 我的笔记              [编辑]  │ │
│  │ 我的理解：般若不同于一般的智慧，  │ │
│  │ 它是指对空性的直接体悟...        │ │
│  │                        2026-05-02│ │
│  └──────────────────────────────────┘ │
│                                        │
│  [+ 添加笔记]                          │
└────────────────────────────────────────┘
```

**分离策略**：
1. **存储分离**：原始释义存于 `dict_entries`，笔记存于 `user_notes`（不同表）
2. **渲染分离**：释义卡片与笔记卡片视觉区分（不同背景色/边框）
3. **编辑权限**：原始释义不可编辑（只读），笔记可自由编辑
4. **合并展示**：弹窗渲染时先展示原始释义，下方追加用户笔记
5. **导出分离**：支持仅导出笔记、仅导出释义、或合并导出

### 5.2 Markdown 编辑器选型

笔记编辑需要轻量级 Markdown 编辑器。以下是选型对比：

| 编辑器 | 包大小 (gzip) | 功能 | 移动端适配 | Vue 3 支持 | 适用性 |
|--------|--------------|------|-----------|-----------|--------|
| **纯 textarea + marked 预览** | ~8KB | 基础编辑 + 实时预览 | 优秀 | 原生 | 推荐 |
| **@kangc/v-md-editor** | ~150KB | 双屏编辑预览、工具栏、代码高亮、公式 | 中等（双屏在移动端拥挤） | 原生 | 过重 |
| **md-editor-v3** | ~120KB | 工具栏、快捷键、主题切换、图片上传 | 中等 | 原生 | 过重 |
| **mavon-editor** | ~200KB | 双屏、公式、流程图 | 差 | 需适配 | 不推荐 |
| **vditor** | ~300KB | 所见即所得、即时渲染、大纲 | 中等 | 需封装 | 过重 |

**推荐方案：纯 textarea + marked 实时预览（轻量模式）**

理由：
1. **佛经笔记场景简单**：用户笔记以文字为主，少量加粗、列表、引用，不需要代码块、公式等复杂功能
2. **包体积最小**：仅依赖 marked（8KB），无额外编辑器组件
3. **移动端体验最佳**：原生 textarea 在移动端键盘兼容性好，无 iframe/iframe 兼容问题
4. **实现简单**：双栏切换（编辑/预览），移动端自动切换为单栏 Tab 模式

**编辑模式设计**：

PC / 平板：
```
┌────────────────────────────────────┐
│  📝 编辑笔记                       │
│  ───────────────────────────────── │
│  ┌──────────┬───────────────────┐  │
│  │ 编辑区    │ 实时预览区         │  │
│  │          │                   │  │
│  │ textarea │ 渲染后的 HTML      │  │
│  │          │                   │  │
│  └──────────┴───────────────────┘  │
│  [保存] [取消]                     │
└────────────────────────────────────┘
```

移动端：
```
┌─────────────────────┐
│  📝 编辑笔记         │
│  ─────────────────── │
│  [编辑 | 预览]  ← Tab│
│  ─────────────────── │
│                     │
│  textarea 或 渲染区  │
│  （二选一显示）      │
│                     │
│  ─────────────────── │
│  [保存]    [取消]    │
└─────────────────────┘
```

### 5.3 笔记搜索和导出

#### 笔记搜索

```
┌────────────────────────────────────────┐
│  🔍 搜索笔记                           │
│  ───────────────────────────────────── │
│  [搜索框：输入关键词...]               │
│                                        │
│  搜索结果：                            │
│  ┌──────────────────────────────────┐ │
│  │ 📌 般若 - 我的笔记               │ │

│  │ 关联经文：心经 · 第一章           │ │
│  │ 2026-05-02                       │ │
│  └──────────────────────────────────┘ │
│  ┌──────────────────────────────────┐ │
│  │ 📌 涅槃 - 我的笔记               │ │
│  │ 涅槃意为"灭度"，指烦恼的...       │ │

│  └──────────────────────────────────┘ │
```

**搜索策略**：
- 全文搜索：在 `user_notes` 表的 `note` 字段中进行关键词匹配
- 关联词条搜索：同时搜索笔记关联的词条名称
- 索引构建：在笔记更新时构建倒排索引（简单实现可使用 `LIKE '%keyword%'`，大规模时使用 IndexedDB 全文搜索）

#### 笔记导出

| 格式 | 用途 | 实现方式 |
|------|------|----------|
| **Markdown** | 导入 Obsidian、Notion 等 | 每个笔记生成独立 `.md` 文件，按词条名命名 |
| **PDF** | 打印、分享 | 使用 `html2canvas` + `jspdf` 或 `window.print()` |
| **JSON** | 数据备份、迁移 | 导出 `user_notes` 表完整数据 |
| **HTML** | 浏览器直接查看 | 生成自包含 HTML 文件 |

**导出流程**：
1. 用户在设置页选择"导出笔记"
2. 选择导出范围和格式
3. 浏览器下载文件

### 5.4 笔记版本历史

**版本管理策略**：

```
Table: note_versions
┌────────────────────┬─────────────┬──────────┬──────────┬──────────┐
| id (PK)            | note_id     | content  | created  │ reason   │
├────────────────────┼─────────────┼──────────┼──────────┼──────────┤
| nv::001            | note::001   | 初始版本  │ ...      │ create   │
| nv::002            | note::001   | 补充说明  │ ...      │ update   │
| nv::003            | note::001   | 修正理解  │ ...      │ update   │
└────────────────────┴─────────────┴──────────┴──────────┴──────────┘
```

**版本交互设计**：

```
┌────────────────────────────────────────┐
│  📝 我的笔记                  [历史 ▼] │
│  ───────────────────────────────────── │
│  当前版本（2026-05-02 14:30）:         │
│  我的理解：般若不同于一般的智慧...      │
│                                        │
│  ┌─ 历史版本 ─────────────────────────┐│
│  │ 2026-05-02 14:30  修正理解  [恢复] ││
│  │ 2026-05-02 10:15  补充说明  [恢复] ││
│  │ 2026-05-01 09:00  初始版本  [恢复] ││
│  └────────────────────────────────────┘│
│                                        │
│  [保存] [取消]                         │
└────────────────────────────────────────┘
```

**版本控制策略**：
- **自动保存**：每次编辑保存时自动创建新版本
- **手动快照**：用户可手动创建版本快照（标注说明）
- **版本数量**：默认保留最近 20 个版本，超出后自动清理最旧版本
- **差异对比**：恢复前可预览两个版本的差异（可选，v2.1 实现）
- **存储优化**：仅存储 diff 而非完整内容（可选优化）

**实现简化方案（v2.0）**：
- 仅保留"最后修改时间"和"当前内容"，不做版本链
- 版本历史列入 v2.1 规划（Phase 3 增强功能已列出"词典版本管理"）

## 6. 笔记理念对比

| 理念 | Notion | Obsidian | 本项目 |
|------|--------|----------|--------|
| **核心定位** | All-in-One 工作台（文档+数据库+协作） | 本地知识网络（双向链接+图谱） | 经文阅读辅助笔记 |
| **数据存储** | 云端（依赖服务） | 本地 Markdown 文件 | IndexedDB（本地） |
| **组织方式** | 树形页面 + 数据库视图 | 双向链接 + 知识图谱 | 词条关联（一对一） |
| **格式** | 富文本 Block（非标准） | 纯 Markdown | Markdown（支持扩展） |
| **笔记粒度** | 文档级（长文） | 原子笔记（短小） | 词条级（短注释） |
| **知识关联** | 手动链接 + @mention | 自动双向链接 + 图谱 | 词条 ↔ 经文位置关联 |
| **协作** | 实时多人协作 | 无（本地优先） | 无（纯个人使用） |
| **扩展性** | 模板市场 + API | 插件生态 | 预留后端 API 接口 |

### 对本项目的启示

1. **从 Notion 借鉴**：
   - 结构化数据意识：笔记可以关联元数据（词条、经文、时间、标签）
   - 模板思维：可提供笔记模板（"个人理解"、"诵读感悟"、"术语辨析"）

2. **从 Obsidian 借鉴**：
   - 本地优先：数据完全存储在 IndexedDB，不依赖云端
   - Markdown 标准格式：笔记可随时导出为标准 `.md` 文件
   - 知识关联：未来可扩展为"词条 ↔ 词条"的关联笔记网络

3. **本项目的独特定位**：
   - **场景聚焦**：不追求通用笔记能力，仅服务于"经文术语理解"
   - **轻量至上**：不需要数据库、协作、插件等复杂功能
   - **禅意体验**：编辑界面极简、无干扰，符合"简单、专注、不打扰"的核心理念

## 7. 结论与建议

### 7.1 弹窗设计结论

| 维度 | 推荐方案 | 理由 |
|------|----------|------|
| **PC 定位** | 跟随高亮词条的浮动弹窗 | 上下文关联清晰，不打断阅读流 |
| **移动端** | 底部抽屉（Bottom Sheet） | 符合移动端操作习惯，Vant 原生支持 |
| **加载策略** | 流式加载（先返回先渲染） | 用户体验好，减少等待感 |
| **默认模式** | 展开首个词典 | 平衡信息量与简洁度（与 D5 一致） |
| **加载反馈** | 骨架屏 + 状态图标 | 明确的进度反馈 |

### 7.2 Markdown 渲染结论

| 维度 | 推荐方案 | 理由 |
|------|----------|------|
| **渲染库** | marked + DOMPurify | 体积最小（8KB）、流式友好、零依赖 |
| **特殊格式** | 自定义 class 包裹梵文/巴利文/藏文 | 保持语义化，支持字体定制 |
| **安全** | DOMPurify 白名单过滤 | 防止 MDX 词典中的 HTML 注入 |

### 7.3 笔记设计结论

| 维度 | 推荐方案 | 理由 |
|------|----------|------|
| **编辑器** | 纯 textarea + marked 预览 | 最轻量（8KB）、移动端兼容性好 |
| **存储** | 与原始释义分离（不同表） | 不破坏原数据（D10） |
| **版本历史** | v2.0 仅保留修改时间，v2.1 实现版本链 | 控制本期范围 |
| **搜索** | 关键词匹配 + 关联词条搜索 | 简单实用 |
| **导出** | Markdown + JSON 格式 | 通用性强，可迁移 |

## 8. 对 v2.1 方案的影响

本分析结果对 v2.1 方案的具体影响：

| 影响项 | 说明 | 优先级 |
|--------|------|--------|
| **笔记版本链** | v2.0 仅保留修改时间，v2.1 需实现 `note_versions` 表和差异对比 | P1 |
| **笔记标签系统** | 支持为笔记添加标签（如"重要"、"待深入"、"感悟"），增强搜索能力 | P2 |
| **笔记模板** | 提供预设模板（个人理解、诵读感悟、术语辨析），降低用户输入门槛 | P2 |
| **词条关联网络** | 支持笔记中引用其他词条（类似 Obsidian 的 `[[双向链接]]`） | P3 |
| **Markdown 公式支持** | 若未来需要渲染梵文转写公式，可引入 KaTeX 插件 | P3 |
| **笔记分享** | 生成笔记卡片图片，分享给同修 | P3 |

### 待 v2.1 细化的开放问题

1. **笔记最大长度限制**：是否需要限制单条笔记的字数？（建议 5000 字）
2. **笔记富媒体支持**：是否允许笔记中插入图片？（v2.0 不支持，v2.1 可考虑）
3. **笔记批量操作**：批量删除、批量导出、批量添加标签
