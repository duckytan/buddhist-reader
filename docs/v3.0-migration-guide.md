# v2.0 → v3.0 迁移指南

> 从 v2.0 迁移到 v3.0 的注意事项

## 架构变化

| 方面 | v2.0 | v3.0 |
|------|------|------|
| UI 组件库 | Vant 4 | 纯手写 |
| 阅读方式 | 分页（2000字/页） | 连续滚动 |
| 词典加载 | 全量加载到内存 | 索引在线 + 释义按需 |
| 状态管理 | Pinia Store 职责交叉 | Pinia Store 职责单一 |
| 存储 | IndexedDB | localStorage |
| 主题 | Vant 主题 + 自定义 | CSS 变量 + data-theme |

## 不兼容变更

### 1. 组件移除

v3.0 不再使用 Vant 组件，以下组件需要重写：

- `van-button` → 自定义 `Button.vue`
- `van-popup` → 自定义 `Popup.vue`
- `van-tabs` → 自定义 `Tabs.vue`
- `van-card` → 自定义 `SutraCard.vue`

### 2. Store 重构

v2.0 的 Store 需要拆分：

```javascript
// v2.0: reader.js 管了 6 件事
// v3.0: 拆分为 4 个 Store
- sutra.js    // 经书数据
- reader.js   // 阅读状态（滚动、书签）
- dict.js     // 词典数据
- setting.js  // 全局设置
```

### 3. 路由变化

v3.0 简化为两个路由：

```javascript
// v3.0 路由
const routes = [
  { path: '/', component: Bookshelf },
  { path: '/reader/:id', component: Reader }
]
```

### 4. 数据格式不变

经书 JSON 和词典 JSON 格式保持不变，可直接复用：

- `public/sutras/*.json`
- `public/dicts/*.json`
- `public/sutras/manifest.json`
- `public/dicts/manifest.json`

## 迁移步骤

### 1. 备份 v2.0

```bash
git checkout -b 260503-archive-v2-final
git push -u origin 260503-archive-v2-final
```

### 2. 清空 src

```bash
rm -rf src/
mkdir -p src/{components,pages,stores,composables,utils,styles}
```

### 3. 复用设计系统

```bash
cp archive/v2.0/src/styles/tokens.css src/styles/
cp archive/v2.0/src/styles/base.css src/styles/
```

### 4. 创建新项目文件

```bash
# package.json
# vite.config.js
# index.html
# src/main.js
# src/App.vue
# src/router/index.js
```

### 5. 逐步迁移功能

按 Phase 顺序：
1. Phase 1: 项目搭建
2. Phase 2: 书架页面
3. Phase 3: 阅读页面基础
4. Phase 4: 词典系统
5. Phase 5: 阅读增强
6. Phase 6: 笔记与统计
7. Phase 7: 联调优化

## 常见问题

### Q: v2.0 的 IndexedDB 数据能迁移吗？

A: v3.0 使用 localStorage，IndexedDB 数据无法直接迁移。用户需要重新设置偏好。

### Q: v2.0 的 Service 层还能用吗？

A: 不建议复用。v2.0 的 Service 层设计不佳，v3.0 使用更简单的 composables。

### Q: 自定义词典还能用吗？

A: 可以。只要格式符合 `public/dicts/*.json` 规范即可。

### Q: 需要重新安装依赖吗？

A: 是的。v3.0 移除了 Vant、idb、mdict-js 等依赖，需要重新 `npm install`。
